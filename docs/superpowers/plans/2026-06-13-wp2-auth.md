# WP2 — Auth (argon2 + JWT) + Consentimento + Perfis — Implementation Plan

> REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`. WSL/quoting: ver [[git-via-wsl]] (`bash -lc` p/ pnpm; git msg aspas simples). Postgres em Docker porta 5433.

**Goal:** API de autenticação própria (registro/login/refresh/logout, hash **argon2**, **JWT** access+refresh com rotação), middleware de auth/RBAC, fluxo de **consentimento parental** (RF-02) com guard, CRUD de `child_profiles` escopado, e fluxo mínimo de login + gate de consentimento no app Expo.

**Architecture:** `@node-rs/argon2` (prebuilt, sem node-gyp) p/ hash; `jsonwebtoken` p/ JWT. Access token curto (15 min) verificado por decorator Fastify → `request.actor = {id, role}`. Refresh token (7 dias) guardado **hasheado** em `refresh_tokens`, rotacionado a cada uso (revoga o anterior). Contratos zod em `packages/shared`. App guarda tokens em `expo-secure-store`, com `AuthContext`.

**Tech:** @node-rs/argon2 · jsonwebtoken · @fastify/cookie (opcional) · zod · expo-secure-store.

**Cobre:** RF-01..04, Seção 11.1 (consentimento), ADR-08.

## Task 3: Rotas de auth + middleware + consentimento

**Files:** `apps/api/src/auth/middleware.ts`, `apps/api/src/routes/auth.ts`, `apps/api/src/repos/consent.ts`, `apps/api/src/app.ts` (registrar rotas)

- [ ] **Step 1:** `auth/middleware.ts`: decorator/preHandler `requireAuth` que lê `Authorization: Bearer`, `verifyAccess`, e seta `req.actor={id,role}`; `requireRole(...roles)`; `requireConsent` (verifica em `consent_records` que o usuário tem `PARENTAL_DATA` granted na `policy_version` vigente — constante `CURRENT_POLICY_VERSION`).
- [ ] **Step 2:** `routes/auth.ts` (registradas em `app.ts` sob `/api/v1`):
  - `POST /auth/register` — valida `RegisterInputSchema`, recusa email duplicado (409), cria user (hash argon2), retorna 201 + tokens (emite refresh + grava hash).
  - `POST /auth/login` — valida, verifica senha, retorna tokens; credenciais inválidas → 401.
  - `POST /auth/refresh` — recebe `{refresh_token}`, `verifyRefresh`, confere hash válido em `refresh_tokens` (não revogado/expirado), **rotaciona** (revoga o atual, emite novo par). Reuso de token revogado → 401.
  - `POST /auth/logout` — revoga o refresh apresentado.
  - `POST /auth/consent` (requireAuth) — grava `consent_records` (valida `ConsentInputSchema`).
- [ ] **Step 3:** `repos/consent.ts`: `recordConsent(...)`, `hasParentalConsent(userId, version)`.
- [ ] **Step 4:** typecheck limpo. Commit: `feat(api): auth routes (register/login/refresh/logout) + consent + guards`.
